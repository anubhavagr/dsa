## 📋 Phase 1 — Requirements (15 min, closed-book — write BEFORE looking at Phase 4)
- [ ] Functional requirements (3–5). Starters — complete/extend:
  - Crawl the top ~1B pages
  - Politeness: never hammer a host
  - Some freshness contract (recrawl cadence)
  - Your additions — robots.txt handling? dedup? JS rendering? Which are P0 vs deferred?
  - Restate the P0s in one crisp sentence before extending: "crawl 1B pages politely on 100 machines in 30-day cycles"
  - Name one adjacent feature you deliberately EXCLUDE, with one sentence why (e.g. the indexing / page-rank side)
- [ ] Non-functional — answer with numbers:
  - Politeness per host: what gap between two fetches to the SAME host, and who enforces it?
  - 100 machines budget — what does that cap first: bandwidth, concurrency, or storage?
  - What's the freshness SLO — days for news sites, weeks for static pages?
  - Every NFR answer ends in a number or a named tradeoff — never an adjective
- [ ] Back-of-envelope done:
  - 1B pages / 30-day cycle → pages/s average, and peak (2–3× average?)
  - Page ~500 KB → raw storage/day and network egress/day
  - Sanity: how many concurrent in-flight fetches does pages/s × latency imply?
  - Arithmetic on the page, not in your head — the interviewer grades the working, not the result

## ✏️ Phase 2 — One-page design (25 min)
- [ ] API / interface sketch
  - Internal interfaces: frontier.pop(host_slot) / frontier.push(urls, priority) / fetcher.fetch(url) → {content, links}
- [ ] Data model + storage choice justified out loud
  - URL-seen set (hash of normalized URL), content store keyed by content hash, per-host queue metadata
- [ ] Box-and-arrow diagram — every box gets a one-line reason
  - Keep it ≤8 boxes; past that, group boxes and name the groups
- [ ] URL frontier designed: per-host FIFO queues for politeness + a global priority heap for importance/freshness
  - The frontier IS the crawler — spend real time here
  - Two dimensions stated: WHICH host next (politeness FIFO) and WHICH url first (priority) — don't merge them
- [ ] Async fetcher pool with bounded per-host concurrency
- [ ] Dedup layers: exact (content hash) + near-duplicate (simhash)
- [ ] Recrawl scheduling by learned churn — pages that change fast get visited fast
- [ ] Scaling story: partition key chosen + hot spots named
  - Shard the frontier by host-hash so all of one host's state lives in one place
- [ ] Failure story: what's lost on crash, replication, honest CAP position
  - A crashed crawler loses in-flight fetches — acceptable; a lost frontier is not — so where does the frontier live?

## 🔥 Phase 3 — Escalations (20 min — answer ALOUD before opening Phase 4)
- [ ] E1: JS-rendered SPAs — what does the render farm look like and what does it cost?

## 📖 Phase 4 — Reference checkpoints (open only AFTER your attempt)
What a strong L5 answer includes:
- Frontier = priority queue OF per-host FIFOs (politeness) + global priority heap (importance/freshness) — two-level structure, stated explicitly
  - Say it: "The frontier is per-host FIFOs under a global priority heap — politeness is a queue property, not a timer."
- DNS caching layer — a crawl at hundreds of pages/s melts uncached DNS
- Async fetchers with bounded concurrency PER HOST, not just globally
- robots.txt respected + cached per host with a TTL
- Exact dedup by content hash; near-duplicate by simhash (say what simhash buys over plain hashing)
  - Say it: "Content hash catches exact dupes; simhash catches the same article with a different timestamp."
- Recrawl priority by churn rate — change frequency learned per page from its own history
  - Say it: "Recrawl priority is learned churn — a page that changes weekly is crawled weekly; the crawler earns its freshness budget."
- Shard the frontier by host-hash so politeness decisions are local, no cross-shard coordination
  - Say it: "Frontier sharded by host-hash — all state for one host in one place, so politeness needs no coordination."
- Render farm = headless-browser pool, ~10–100× the cost of a plain fetch — gate it: only render when the plain fetch looks empty
  - Say it: "A headless fetch is 10–100× a plain GET — render only when the plain fetch comes back hollow."
- Poison hosts → timeout + exponential backoff + quarantine (circuit breaker at the per-host queue)
- Link graph + page store are SEPARATE systems — say the boundary; the crawler feeds them, it isn't them
- Math said cold: 1B / 30 days ≈ 386 pages/s average, peaks 2–3×
  - Say it: "A billion pages over thirty days is ~386 pages a second average, 2–3× at peak — politeness, not bandwidth, is the binding constraint."
