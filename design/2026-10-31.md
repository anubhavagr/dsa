## 📖 Phase 4 — Reference checkpoints (open only AFTER your attempt)
What a strong L5 answer includes:
- OT = central server serializes + transforms incoming ops (Google's historical choice); say what the server IS in this design
  - Say it: "The server is the serializer — every op is transformed against everything that landed first."
- CRDT (RGA/text) = monotonic merge, no central authority — but pays metadata cost per character; the tradeoff stated, not just named
  - Say it: "CRDTs merge monotonically with no leader — the price is per-character metadata forever."
- Document stored as an op log with periodic snapshot compaction — replay from snapshot + tail
- Never ship the full doc — deltas only, in both directions
  - Say it: "The doc is an op log plus snapshots — deltas only, in both directions, forever."
- Per-user undo = inverse ops applied against CURRENT state — requires transforming the inverse over later interleaved ops; that's why undo is hardest
  - Say it: "Undo is an inverse op applied to current state, transformed over every op that interleaved — which is why it's the hardest op."
- Presence/cursors = ephemeral multicast, NOT in the op log — different durability and consistency class
  - Say it: "Cursors are ephemeral multicast — losing one is invisible; losing a character is a bug report."
- Offline = client-side buffer with lamport/vector clocks; replay with server-side ordering on reconnect
- Fan-out via pub/sub between websocket servers keyed by doc room
- Durability = WAL + replication before ack of durability-critical ops (never lose text); local echo needs no ack
- CAP split stated: availability beats consistency for cursors/presence; consistency beats availability for text ops
  - Say it: "Availability for cursors, consistency for characters — two consistency classes in one product, by design."
