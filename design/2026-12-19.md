## ✏️ Phase 2 — One-page design (25 min)
- [ ] API / interface sketch
  - uploadSession(chunk hashes) → missing chunks; finalize → photo_id; search(query | face_id); share(album_id, principals)
- [ ] Data model + storage choice justified out loud
  - Content-addressed blobs (dedup'd globally) + per-user metadata in a consensus-backed store — two stores, two consistencies, say it
- [ ] Box-and-arrow diagram — every box gets a one-line reason
  - Keep it ≤8 boxes; past that, group boxes and name the groups
- [ ] Chunked resumable upload tuned for flaky mobile: smaller chunks, retry per chunk, hash-per-chunk
- [ ] Multi-region storage with erasure coding across zones/regions
- [ ] Async ML pipeline: upload → queue → vision models → tags / faces / embeddings → per-user search index
  - Ingest must NEVER wait on a model — the queue between them is the architectural point; say it
- [ ] Albums and sharing as METADATA (ACL tokens) over deduped blobs — a share never copies bytes
- [ ] Thumbnail strategy: pre-generate 2–3 sizes (timeline, grid, full) at ingest
- [ ] Scaling story: partition key chosen + hot spots named
  - Metadata partitioned by user; blobs by content hash; hot spot = one user's 100k-photo import — throttled, not crashed
- [ ] Failure story: what's lost on crash, replication, honest CAP position
  - Blob durability is erasure-coded 11-nines; metadata consensus per user; search index may trail (rebuildable) — three different stories, all said

## 🔥 Phase 3 — Escalations (20 min — answer ALOUD before opening Phase 4)
- [ ] E1: 'instant upload' — the hash exists globally: what must be true about your content addressing for this to be safe, and what leaks (privacy!) if done naively?
  - Probe: hash-existence is an oracle — what does a probe of "does this hash exist?" reveal, and to whom?
  - Probe: rate-limit the hash oracle — but what does the RATE LIMIT itself leak to a patient attacker?
- [ ] E2: consensus for metadata: why Spanner-style (or per-user consensus units) instead of one global DB?
  - Probe: what does a single global consensus domain cost at write QPS = every user's every photo?
- [ ] E3: face groups across a user's library — incremental clustering, not re-cluster: how?
  - Probe: one new photo joins 12,000 existing ones — what is NOT recomputed?
  - Then raise one escalation YOURSELF — the one you hope they don't ask — and answer it

## 📖 Phase 4 — Reference checkpoints (open only AFTER your attempt)
What a strong L5 answer includes:
- Resumable chunked uploads tuned for flaky mobile — smaller chunks, per-chunk retry, per-chunk hashes
- Content-addressed blobs → dedup — BUT hash-existence must not leak cross-user information: per-user namespace confirmation, rate-limited probing
  - Say it: "Hash-existence is an oracle — confirm within a per-user namespace and rate-limit the probing."
- Erasure coding across zones/regions for 11 nines — plain 3× replication is 3–5 nines class; you say the arithmetic of why
  - Say it: "Triple replication is 3–5 nines class; 11 nines wants erasure coding spread across zones and regions."
- Metadata = per-user rows in a consensus-backed store (Spanner-class) — the USER is the consistency unit, not the planet
  - Say it: "The USER is the consistency unit — per-user consensus domains, not one global database."
- ML pipeline fully async: upload → queue → vision models → tags/faces/embeddings → per-user index — ingest never waits on a model
  - Say it: "Upload returns the moment bytes are durable; models run later from a queue; search trails by minutes."
- Thumbnails pre-generated at 2–3 sizes (timeline, grid, full) — timeline scrolling never decodes originals
  - Say it: "Two or three thumbnail sizes at ingest — the timeline never decodes an original."
- Timeline = date-ordered index pagination — the DEFAULT view is an index scan, design for it
- Sharing = ACL tokens on album metadata; the media itself stays deduped — no byte copies on share
- Faces = incremental clustering with stable cluster IDs — a new photo merges into affected clusters only, never a library-wide re-cluster
  - Say it: "A new photo merges into the clusters it touches — stable cluster IDs mean no library-wide re-cluster."
