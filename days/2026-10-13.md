## 🔥 Pattern of the Day: Fast/slow with a fixed gap
Two walkers on the same list, one ahead of the other by exactly k nodes: when the leader falls off the end, the follower is standing somewhere interesting — k from the end, the middle, or just before a deletion.
Same speed, different starting lines — that is the whole trick, and it converts "count first, walk again" into one pass.
Cycles are the same idea at different speeds: a faster runner on a loop must lap a slower one, and resetting one walker to the head turns the meeting point into the entry finder.
Reach for two walkers whenever a problem says kth from the end, middle, or cycle.
Invariant: the distance between the two walkers never changes until the leader hits None.

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val, self.next = val, next

def remove_nth_two_pass(head, n):     # pass 1: count; pass 2: walk to victim
    length, node = 0, head
    while node:
        length += 1
        node = node.next
    dummy = node = ListNode(0, head)
    for _ in range(length - n):
        node = node.next
    node.next = node.next.next
    return dummy.next
```

```python
def remove_nth_from_end(head, n):
    dummy = slow = ListNode(0, head)  # dummy: deleting the head is uniform
    fast = head
    for _ in range(n):                # fast leads slow by exactly n nodes
        fast = fast.next
    while fast:                       # both advance until fast falls off
        fast, slow = fast.next, slow.next
    slow.next = slow.next.next        # slow sits just before the victim
    return dummy.next

def middle(head):
    slow = fast = head
    while fast and fast.next:         # 2x speed: slow is at mid at the end
        slow = slow.next
        fast = fast.next.next
    return slow
```

Watch-outs:
- Start `fast` from `head` and `slow` from `dummy`, not both from dummy — off-by-one in the gap is the classic bug; test on a list of exactly n nodes.
- For cycle entry: after the meeting, walk one pointer from the head and one from the meeting point at the SAME speed — they meet at the entry. Be ready to sketch why (the leftover distance equals the head-to-entry distance).
- Merge-k is tomorrow's Hard because "which node is smallest across k lists" needs a structure, not more pointers.
