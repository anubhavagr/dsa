## 🔥 Pattern of the Day: Backtrack over positions, test constraints in O(1)
Constraint boards (queens, sudoku, IP chunks) are still choose → explore → un-choose — the new skill is making the constraint check O(1) instead of O(board).
Encode every attack line as a set: a queen at (r, c) attacks column c, diagonal r+c, and anti-diagonal r−c — membership tests replace board rescans.
Fixing one placement per recursion level (a queen per row, a cut per segment) gives the tree a fixed shape and a clean base case.
Prune hard: a candidate that attacks anything is skipped before the recursive call — the sets make skipping free.
Invariant: the three sets contain exactly the lines occupied by the queens on the current path — no more, no less.
Complexity to narrate: worst case stays exponential — the sets shrink the CONSTANT of each node's conflict test from O(n) to O(1), not the tree's size; say both halves of that sentence.
Sudoku is the same skeleton with three families of sets (rows, columns, boxes) and empty cells instead of rows — box index r//3 * 3 + c//3 is the only new arithmetic.
Restore IP is the string-cutting cousin: the "board" is the string, the position is a cut index, and the constraint check is a format rule instead of an attack set.
When asked "how would you make it faster?", the honest answers are better pruning and smarter ordering (most-constrained cell first) — name them, do not hand-wave.
Trace n = 4 by hand once: the tree is small enough to draw whole, and that drawing is what you will rebuild from memory in the interview.

```python
def solve_n_queens(n):
    out, board = [], []
    cols, diag, anti = set(), set(), set()   # occupied lines, O(1) conflict tests
    def backtrack(row):
        if row == n:                          # every row placed -> a solution
            out.append(board[:])
            return
        for c in range(n):
            if c in cols or (row + c) in diag or (row - c) in anti:
                # O(1) attack test: three set memberships, no board rescan
                continue                      # attacked square: prune before recursing
            board.append('.' * c + 'Q' + '.' * (n - c - 1))
            cols.add(c); diag.add(row + c); anti.add(row - c)      # choose
            backtrack(row + 1)                # explore one row deeper
            board.pop()
            cols.discard(c); diag.discard(row + c); anti.discard(row - c)  # un-choose
    # row 0 starts clean: every column is a candidate
    backtrack(0)
    return out                        # exponential worst case, tiny in practice
```

Watch-outs:
- One queen per row is what makes the recursion depth n — that single decision, justified aloud, is most of the interview credit.
- The un-choose for sets is discard on the same objects — mutate the three sets down and back up the tree; never build fresh sets per call.
- Restore IP's leading-zero rule kills "01" but keeps "0" — that one-character distinction causes most of the wrong submissions.
- Sudoku's box index (r//3*3 + c//3) deserves a one-line derivation on the whiteboard — interviewers probe it.
- N-Queens sanity counts worth knowing cold: n=1 → one solution, n=2 and n=3 → none, n=4 → two.
- Diagonal identity: cells on the same "\" diagonal share r−c; same "/" share r+c. Derive it, do not memorize it — write the four corners of a square and check.
