## 🔥 Pattern of the Day: The first-true boundary
Every boundary question — first occurrence, last occurrence, first index ≥ x, latest version ≤ t — is the same question: where does a boolean predicate flip from false to true along an ordered axis?
Write the predicate, aim bisect_left at it, and the index that comes back IS the answer; range ends are just two boundaries minus one.
Reach for it whenever "sorted" or "append-only over time" appears in the statement.
Invariant: everything before lo fails the predicate, everything from hi onward satisfies it — they converge exactly at the flip point.
Complexity to narrate: each boundary costs one O(log n) search — two boundaries is still O(log n); the linear scan you are replacing was O(n) and quietly said "I never noticed it was sorted."
The 2D shortcut is index arithmetic: treat an m×n matrix as m·n sorted cells, search over [0, m·n), and decode mid into (mid // n, mid % n) — no copy, one line.
When only ROWS are sorted (each row sorted, not row-to-row), the shortcut dies: you get n binary searches or a staircase walk from a corner — the statement's exact promise decides which.
Time-based storage is the pattern in disguise: an append-only history per key IS sorted by time, and "latest value at or before t" is a first-true boundary on timestamps.
Once you see every boundary question as one predicate flip, bisect stops being a utility and becomes a language — you will read "first version that passes" problems the same way tomorrow.

```python
def search_range_linear(nums, target):   # O(n) — ignores the sorted order
    hits = [i for i, v in enumerate(nums) if v == target]
    return [hits[0], hits[-1]] if hits else [-1, -1]
```

```python
def bisect_left(a, x):
    lo, hi = 0, len(a)              # invariant: a[:lo] < x, a[hi:] >= x
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:              # predicate: "a[mid] < x" — false side first
            lo = mid + 1
        else:
            hi = mid
    return lo                       # the flip point: first a[i] >= x

def search_range(nums, target):
    start = bisect_left(nums, target)
    if start == len(nums) or nums[start] != target:
        return [-1, -1]                # boundary past the end, or wrong value
    return [start, bisect_left(nums, target + 1) - 1]   # first >= target+1,
                                                        # minus one = last == target
```

Watch-outs:
- "Last occurrence of x" is "first occurrence of anything greater, minus one" — the target+1 trick only works on integers, so say that caveat aloud.
- bisect_right solves the mirror question (first index strictly past x) — decide which boundary your predicate needs before writing either.
- Test [5,7,7,8,8,10] with target 8 AND target 6 — one hits, one misses, and together they catch most boundary bugs in this family.
- An empty matrix and a 1×1 matrix are the two structural tests for the index-arithmetic version — run both before declaring done.
- The row-major trick needs the promise that the first element of each row is greater than the last of the previous row — without it, you get n independent binary searches instead.
- An empty array must return lo = 0 without indexing anything — check your boundary lines against [] before declaring done.
