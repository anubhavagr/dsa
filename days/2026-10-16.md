## 🔥 Pattern of the Day: The monotonic stack
Keep a stack of things still waiting for their resolution, ordered so the arrival of anything "better" resolves a whole suffix at once.
Next-greater: the stack holds indices whose values decrease downward; a new value pops every smaller thing above it — and each pop IS an answer ("you are my next greater").
The deque version keeps that discipline inside a window: indices in decreasing value order, front is the current max, and eviction happens for two reasons (out of window, dominated).
Reach for it on next/previous greater, spans, histogram areas, and window maxima — anywhere an arrival resolves a batch of waiters.
Invariant: the stack's values are strictly decreasing from bottom to top; anything that would break it gets resolved first.
Complexity to narrate: each index is pushed once and popped at most once, so the whole scan is O(n) despite the nested while — deliver that amortized line unprompted.
The deque variant adds a second eviction reason: indices leave not only when dominated but when they slide out of the window — two while-loops, both shrinking the structure.
Histogram and next-greater are one machine with different bookkeeping: one stores indices to read heights later, the other reads values immediately — know which yours needs.
Why strictly decreasing and not non-increasing? Equal values would pop each other early and blur "next strictly greater" against "next greater-or-equal" — decide which the problem wants.
Sliding-window-maximum's deque holds INDICES in decreasing value order with the max at the front — popping from the back on entry and from the front on expiry are two different loops.

```python
def daily_temperatures(T):
    res = [0] * len(T)
    # default 0: assume no warmer day until one arrives
    stack = []                        # indices of days still awaiting warmth,
    for i, t in enumerate(T):         # temperatures strictly decreasing
        while stack and T[stack[-1]] < t:
            j = stack.pop()           # today IS the next-warmer day for j
            res[j] = i - j            # resolution time minus wait start
            # one pop = one answer, never revisited
        stack.append(i)               # now today waits its turn
    return res                        # unresolved days keep 0 — correct

def next_greater(nums):               # the same machine, values not gaps
    res = [-1] * len(nums)
    # default -1: nothing has dominated these yet
    stack = []
    for i, x in enumerate(nums):
        while stack and nums[stack[-1]] < x:
            res[stack.pop()] = x      # x resolves everything it dominates
        stack.append(i)
    return res                        # leftovers keep -1 — nothing dominated them
```

Watch-outs:
- Every element is pushed once and popped at most once — that is the amortized O(n) argument; deliver it before the interviewer asks.
- Store indices, not values, whenever an answer needs positions (gaps, widths, window bounds) — values alone cannot tell you how far back an element sat.
- The unresolved leftovers at the end are an answer too ("nothing greater exists") — initialize results to that default before the scan starts.
- Test strictly-decreasing [5,4,3,2,1] and strictly-increasing [1,2,3,4,5]: one exercises only pushes, the other only pops.
- Histogram: a bar's rectangle is capped the moment a strictly shorter bar arrives — what the stack stores (indices!) and what the pop computes (width via the new top) is the whole Hard problem.
- Window max stores indices, never values — you need the index to know whether the front has slid out of the window.
