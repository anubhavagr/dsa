## 🔥 Pattern of the Day: Memo → Table → Rolling Pair
DP is recursion plus reuse: define `f(i)` as the best answer for a suffix, write the recurrence from the *last choice* made at i, and then translate.
Top-down (memo) states the recurrence directly; bottom-up (tabulation) iterates in dependency order with no stack; and when `f(i)` reads only `f(i+1)` and `f(i+2)`, the whole table collapses to two rolling variables. The trained skill is the middle step: saying the state definition out loud before writing any loop.

- **Reach for it when:** the brute force recomputes overlapping subproblems (count ways / min cost / max loot over a sequence).
- **Key invariant:** every table entry is computed only from entries already final.
- **Watch out:** off-by-one in the base cases — the empty input is always a state.
- **Interview soundbite:** "Same recurrence three ways — the state definition is the real work."
- **Test out loud:** n = 0, 1, 2 · empty array · a two-house street.
- **Cost:** O(n) time; the table is O(n) space, the rolling pair is O(1).

```python
from functools import lru_cache

def rob_memo(nums):                       # 1) top-down: recursion + cache
    @lru_cache(None)
    def f(i):                             # f(i): best loot from house i on
        if i >= len(nums):
            return 0
        return max(nums[i] + f(i + 2),    # rob i, jump to i+2
                   f(i + 1))              # or skip i
    return f(0)

def rob_table(nums):                      # 2) bottom-up: same recurrence
    dp = [0] * (len(nums) + 2)            # dp[i] mirrors f(i)
    for i in range(len(nums) - 1, -1, -1):
        dp[i] = max(nums[i] + dp[i + 2], dp[i + 1])
    return dp[0]

def rob_rolling(nums):                    # 3) only two states survive
    take, skip = 0, 0                     # best ending with prev robbed/skipped
    for x in nums:
        take, skip = skip + x, max(take, skip)
    return max(take, skip)
```
