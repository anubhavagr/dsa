## 🔥 Pattern of the Day: In-Place Matrix Rotations & Iterative Fast Pow
A 90° clockwise rotation is the composition of two cheap symmetries: transpose
across the main diagonal (swap matrix[i][j] with matrix[j][i], upper triangle
only), then reverse every row. Both are in-place, so the whole rotation is O(1)
extra memory — and composing the OTHER orders gives the other rotations/reflections,
worth deriving once so you can answer any variant. Fast pow: keep the loop
invariant res · xⁿ = x^N (the original exponent) throughout. Each step squares x
and halves n; whenever n's low bit is 1, bank the current square into res. That's
the multiplicative analogue of the digits of n in binary selecting which precomputed
powers to multiply. Negative n: invert once, up front — and watch the interview
edge case where n is the most negative 32-bit value, whose negation overflows in
fixed-width languages (harmless in Python, worth SAYING).

```python
def rotate(matrix: list[list[int]]) -> None:
    n = len(matrix)
    for i in range(n):                 # transpose across the main diagonal, in place
        for j in range(i + 1, n):      # upper triangle only, or you swap twice
            matrix[i][j], matrix[j][i] = matrix[j][i], matrix[i][j]
    for row in matrix:
        row.reverse()                  # then reverse each row -> 90 degrees clockwise

def my_pow(x: float, n: int) -> float:
    if n < 0:
        x, n = 1 / x, -n               # fold the sign in once, up front
    res = 1.0
    while n:                           # invariant: res * x**n == x**N at all times
        if n & 1:                      # this binary digit of n is set:
            res *= x                   # bank the current square
        x *= x                         # x, x^2, x^4, x^8, ...
        n >>= 1
    return res
```

**Worked example A — rotation** of a 3×3:

```
1 2 3      transpose      1 4 7      reverse rows      7 4 1
4 5 6   -------------->   2 5 8   --------------->     8 5 2
7 8 9                     3 6 9                        9 6 3
```

Check the element mapping against the formula: (i, j) → (j, n-1-i). E.g. 4 at
(1, 0) lands at (0, 2). Trace one more element yourself to lock it in.

**Worked example B — `my_pow(3, 13)`**, 13 = 1101₂:

| bit of 13 (LSB first) | x (current square) | bank it? | res |
|---|---|---|---|
| 1 | 3 | yes | 3 |
| 0 | 9 | no | 3 |
| 1 | 81 | yes | 243 |
| 1 | 6561 | yes | 1594323 |

3 · 81 · 6561 = 3^13 = 1594323 — four iterations instead of twelve multiplies.
