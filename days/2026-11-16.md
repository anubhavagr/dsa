## 🔥 Pattern of the Day: Dijkstra with Lazy Deletion
BFS handles unit weights because one step is one cost. Dijkstra generalizes to non-negative weights by always settling the closest unfinalized node — which a min-heap hands you in O(log n).
Push relaxed candidates eagerly; a node may sit in the heap several times, and a later, worse pop is skipped with `if u in dist: continue` (lazy deletion — no decrease-key in Python). The invariant that makes it all correct: the first time a node leaves the heap, that distance is final. Negative edges break the invariant (that's Bellman-Ford territory).

- **Reach for it when:** edges carry non-negative weights and you need shortest paths from a single source — a negative edge breaks the first-pop-is-final guarantee, and that case calls for Bellman-Ford instead.
- **Key invariant:** A heap entry whose node is already settled (already present in the final dist map) is always safe to discard, because its distance can only be worse than the settled one — this is what makes lazy deletion correct.
- **Watch out:** Forgetting the settled-node skip (`if u in dist: continue`) is not merely slow — an outdated heap entry pops with a stale, larger distance and relaxes neighbors from the wrong value, corrupting the final answers.
- **How to say it in an interview:** "The min-heap always hands me the closest unfinalized node, and the first time a node is popped its distance is final, because everything left in the heap is farther. A node may sit in the heap several times since I push relaxed candidates eagerly, so on each pop I check whether the node is already settled and skip stale entries — that is lazy deletion, which stands in for the decrease-key operation Python's heapq lacks."
- **Test with:** an unreachable node (its distance must stay infinity) · a single-node graph (distance 0, no relaxations) · zero-weight edges (equal-cost ties must not re-settle an already-final node).
- **Complexity:** Each edge relaxation pushes at most one heap entry, so the heap performs O(E) pushes and pops at O(log V) each, giving O((V + E) log V) overall with lazy deletion.

```python
import heapq
from collections import defaultdict

def dijkstra(n, edges, src):              # edges: (u, v, w) with w >= 0
    adj = defaultdict(list)
    for u, v, w in edges:
        adj[u].append((v, w))
        adj[v].append((u, w))             # drop this line if directed
    dist = {}
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if u in dist:                     # stale entry: lazy deletion
            continue
        dist[u] = d                       # invariant: first pop is FINAL
        for v, w in adj[u]:
            if v not in dist:             # settled nodes never improve
                heapq.heappush(pq, (d + w, v))
    return dist                           # missing key = unreachable
```
