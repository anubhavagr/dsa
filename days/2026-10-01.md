## 🔥 Pattern of the Day: Fixed window + need/have
A fixed window of size k over a sequence: when it slides one step, exactly one element enters and one leaves, so every window statistic updates in O(1) — total O(n), no rescans.
The trap is equality bookkeeping when the statistic is "does the window contain a multiset?": compare counts with a have/need score of how many distinct letters meet their quota, not by diffing whole arrays.
Reach for it the moment the problem names a fixed length: "substring of length p", "subarray of size k".
Invariant: after the evict step, `have` equals the number of letters whose window count exactly matches its needed count.

```python
def find_anagrams_brute(s, p):         # O(n * k log k): rebuild every window
    target = sorted(p)
    return [i for i in range(len(s) - len(p) + 1)
            if sorted(s[i:i + len(p)]) == target]
```

```python
from collections import Counter

def find_anagrams(s, p):
    need = Counter(p)                  # required count per letter
    window = Counter()
    have, want = 0, len(need)          # letters whose quota is exactly met
    out = []
    for i, ch in enumerate(s):
        window[ch] += 1
        if window[ch] == need[ch]:
            have += 1                  # this letter just reached its quota
        elif window[ch] == need[ch] + 1:
            have -= 1                  # this letter just overshot it
        if i >= len(p):                # window is too wide -> evict s[i-k]
            left = s[i - len(p)]
            if window[left] == need[left]:
                have -= 1              # about to drop below quota
            elif window[left] == need[left] + 1:
                have += 1              # falling back down to quota
            window[left] -= 1
        if have == want:               # every quota exact == anagram window
            out.append(i - len(p) + 1)
    return out
```

Watch-outs:
- `window[ch] == need[ch]` is False for letters not in `p` because `need[ch]` is 0 — Counter's default does the filtering for you.
- The elif branches are the whole game: without them a letter that overshoots its quota still counts as satisfied and you leak wrong answers.
- Sum windows (max average, max sum) need none of this — one add and one subtract; reach for need/have only on multiset matching.
