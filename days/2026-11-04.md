## 🔥 Pattern of the Day: Sort by the Endpoint That Answers the Question
Merging cares about starts: after sorting, each interval either overlaps the last merged block (`start <= last_end`) or opens a new one — and `max()` on the end absorbs nesting.
The removal/max-non-overlap family cares about ends: among overlapping candidates, keeping the one that ends earliest frees the most room for everything after it. Both are one sort plus one linear sweep holding a remembered `last_end` — that variable is the whole algorithm.

- **Reach for it when:** the input is a set of ranges and the operation is merging, inserting, removing to make the rest non-overlapping, counting rooms, or bursting balloons.
- **Key invariant:** During the sweep, the remembered variable `end` always equals the furthest right edge of every interval kept so far — exactly the value the next interval's start must be compared against.
- **Watch out:** Sorting by the wrong endpoint is the most common interval bug: merging requires sorting by start, while the greedy keep-the-earliest-ending choice requires sorting by end — swap them and both algorithms silently return wrong answers.
- **How to say it in an interview:** "Sorting intervals by start turns merging into one linear sweep: each interval either overlaps the last merged block (its start is at or before the remembered end) or opens a new block, with max() on the ends absorbing nesting. For the removal and max-non-overlap family I sort by end instead, because among overlapping candidates the one that ends earliest frees the most room for everything after it."
- **Test with:** two intervals touching at an endpoint, [1,4] and [4,5] (agree with the interviewer whether touching counts as overlapping) · two identical intervals · a single interval.
- **Complexity:** Sorting the intervals costs O(n log n) and the subsequent sweep is O(n), so the sort dominates the running time — the linear pass adds almost nothing.

```python
def merge(intervals):                     # overlap question -> sort by START
    intervals.sort()
    out = []
    for s, e in intervals:
        if out and s <= out[-1][1]:       # touches the last merged block
            out[-1][1] = max(out[-1][1], e)   # max() absorbs nesting
        else:
            out.append([s, e])            # disjoint: start a new block
    return out

def max_non_overlapping(intervals):       # removal question -> sort by END
    end, kept = float('-inf'), 0
    for s, e in sorted(intervals, key=lambda iv: iv[1]):
        if s >= end:                      # starts after last kept ends
            kept += 1
            end = e                       # earliest end frees the most room
    return kept

def min_arrows(points):                   # LC 452: reuse the current arrow
    arrows, shot_to = 0, float('-inf')
    for s, e in sorted(points, key=lambda p: p[1]):
        if s > shot_to:                   # old arrow can't reach: shoot new
            arrows += 1
            shot_to = e                   # at the earliest end
    return arrows
```
