## 🔥 Pattern of the Day: Converging pointers
Sorted input plus a pair goal means you can start one pointer at each end and let every comparison eliminate a candidate permanently — O(n) after the sort, O(1) space.
The move is never a guess: the sum tells you which pointer to advance, and the reason you can say aloud ("too small → nums[lo] cannot pair with anything better") is the correctness proof.
Reach for it on sorted arrays/strings whenever a pair, palindrome, or symmetry is involved.
Invariant: if an answer pair exists, both of its elements are still in [lo, hi]; everything outside was eliminated with a stated reason.
Complexity story to tell out loud: O(n log n) to sort if the input is unsorted, then one O(n) sweep with O(1) extra space — versus yesterday's hash map at O(n) time and O(n) space.
The pattern scales by pinning elements: fix nums[i], run converging pointers on the remainder — that is the whole step from 2Sum to 3Sum, and pinning again climbs toward kSum.
The palindrome variant swaps the sum for a mirror test (s[lo] against s[hi]) — same skeleton, and it returns tomorrow wearing a delete-one forgiveness.
Never let the pointers cross without checking equality — the `lo < hi` loop guard is what stops an element from pairing with itself.
In the room, trace one full example on the sorted array before typing — say each elimination out loud as you move a pointer.

```python
def two_sum_sorted_hash(numbers, target):   # works — but O(n) space and it
    seen = {}                               # ignores the sortedness you were handed
    for i, x in enumerate(numbers):
        if target - x in seen:
            return [seen[target - x] + 1, i + 1]
        seen[x] = i
    return []                          # (its one edge: works on ANY input order)
```

```python
def two_sum_sorted(numbers, target):
    lo, hi = 0, len(numbers) - 1        # invariant: any answer pair is in [lo, hi]
    while lo < hi:
        s = numbers[lo] + numbers[hi]
        if s == target:
            return [lo + 1, hi + 1]     # 1-indexed, per the problem statement
        if s < target:
            lo += 1                     # numbers[lo] just failed with the LARGEST
        else:                           # partner it will ever see — retire it
            hi -= 1                     # numbers[hi] failed with its SMALLEST
    return []                           # range emptied: no pair sums to target
```

Watch-outs:
- The elimination sentence is the interview — practice saying it, not just typing it.
- In 3-style problems, de-duplicate at the moment you record a triple, never by filtering the output at the end.
- If the input is not sorted, either sort first (say the O(n log n)) or switch to a hash map — converging pointers silently lie on unsorted data.
- 2Sum → 3Sum → kSum is a pin-and-recurse ladder; naming that ladder unprompted when asked about follow-ups is senior-level signal in exactly this family.
- Test the converging template on a two-element array and on no-match input — that pair is the whole boundary suite for the template itself.
- The janitor loops (skip non-alphanumerics, skip duplicate values after a hit) carry most of the bug risk — give them their own tests, not just the main path.
