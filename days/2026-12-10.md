## 🔥 Pattern of the Day: Partition thinking (+ the builder stack)
Google's most-rejected array question is really a question about *cuts*: once you decide how many elements array A contributes to the left half, everything else is forced, and the cut is correct exactly when max(left) ≤ min(right). So binary-search the size, not the value — and guard the edges with ±∞. When the input is a string assembled in nested pieces, the same "decide locally, defer globally" instinct says: park the suspended context on a stack until its closing token arrives.

```python
def kth_smallest(a: list[int], b: list[int], k: int) -> int:
    # Binary-search the SIZE i of a's left part; j = k - i is forced.
    # Cut is valid iff max(left) <= min(right).
    if len(a) > len(b):
        a, b = b, a                    # binary-search the shorter array
    lo, hi = max(0, k - len(b)), min(len(a), k)   # keeps j = k - i legal
    while True:
        i = (lo + hi) // 2             # a[:i] goes left, b[:j] goes left
        j = k - i
        a_l = a[i - 1] if i else float("-inf")
        b_l = b[j - 1] if j else float("-inf")
        a_r = a[i] if i < len(a) else float("inf")
        b_r = b[j] if j < len(b) else float("inf")
        if a_l <= b_r and b_l <= a_r:  # invariant of a valid cut
            return max(a_l, b_l)       # kth smallest = max of the left side
        if a_l > b_r:                  # a contributed too many
            hi = i - 1
        else:                          # a contributed too few
            lo = i + 1
# Median: odd total -> kth((n+1)//2); even -> avg of kth(n//2), kth(n//2+1).
# Builder stack (decode string): on "[" push (string_so_far, repeat);
# on "]" pop, multiply, and stitch back — the frozen context thaws in LIFO order.
```
