## 🔥 Pattern of the Day: Kahn's In-Degree Peel
Count each node's in-degrees once; every node at zero has no prerequisites and enters the queue immediately.
Pop a finished node, decrement each dependent's in-degree — anyone hitting zero just had their last prerequisite satisfied and becomes ready. If the output misses nodes, a cycle swallowed them: the peel IS cycle detection. Variants reuse the same loop with a different queue: a heap gives the lexicographically smallest order; peeling the outer layer repeatedly finds the graph's center.

- **Reach for it when:** the problem is dependencies and ordering — course prerequisites, build steps, package installs, any "must come before" relation — and you need a valid order or a cycle check.
- **Key invariant:** A node enters the queue at the exact moment its in-degree reaches zero — never while a prerequisite is still unprocessed — so the queue order is always a valid execution order.
- **Watch out:** Count in-degrees exactly as the edge list is given — if the same directed edge appears twice, the adjacency list and the in-degree count must both treat it the same way, otherwise a decrement goes missing, a node never reaches zero, and a valid order is falsely reported as a cycle.
- **How to say it in an interview:** "I count each node's in-degree once; a node at zero has no prerequisites, so it is ready and enters the queue immediately. Each time I pop a finished node I decrement the in-degree of every node that depends on it, and anyone reaching zero has just had their last prerequisite satisfied. If the algorithm ends with nodes left unprocessed, those leftovers form a cycle — the same loop is the cycle detector."
- **Test with:** a graph with no edges (every node is ready immediately) · a duplicated directed edge (its adjacency entry and in-degree count must stay consistent) · a self-loop (that node can never reach in-degree zero).
- **Complexity:** With a plain FIFO queue each node is enqueued once and each edge causes one decrement, giving O(V + E); swapping the queue for a min-heap yields the lexicographically smallest valid order at an extra O(log V) per operation.

```python
from collections import deque

def topo_order(n, prereqs):               # prereqs: (before, after)
    adj = [[] for _ in range(n)]
    indeg = [0] * n
    for u, v in prereqs:
        adj[u].append(v)
        indeg[v] += 1

    q = deque(i for i in range(n) if indeg[i] == 0)   # ready: no prereqs
    order = []
    while q:
        u = q.popleft()
        order.append(u)
        for v in adj[u]:                  # u is done: relax dependents
            indeg[v] -= 1
            if indeg[v] == 0:             # ticket punched: now ready
                q.append(v)
    return order if len(order) == n else None           # leftover = cycle

def can_finish(n, prereqs):               # LC 207: the peel detects the cycle
    return topo_order(n, prereqs) is not None
```
