## 🔥 Pattern of the Day: Choose → explore → un-choose
Backtracking is DFS over a decision tree with the discipline of cleaning up: whatever you mutate to mark a choice (a used flag, a board cell, a path list) you restore on the way out.
Permutations differ from subsets in one structural way: order matters, so at every depth you try every not-yet-used element — the used[] array replaces the start index.
On grids the same skeleton walks cells: mark the cell, recurse into neighbors, unmark — the mark IS the "path cannot cross itself" rule.
Prune at the cheapest point possible: an invalid prefix should die before recursing deeper, never after.
Invariant: on entry to each call, the shared state reflects exactly the choices on the current path — and on exit it reflects none of them.
Complexity to narrate: the permutation tree has n! leaves at depth n — say "n factorial" out loud, because that number is why pruning and early returns matter here.
Compare with yesterday in one line: subsets answers "in or out" per element (start index), permutations answers "who is next" per position (used[]) — same skeleton, different branching rule.
Grid walking is the same discipline with one extra move: mark on entry, unmark on exit — the mark is what turns a flood fill into a PATH search.
The un-choose lines must run on failure paths too: every return between choose and un-choose has to pass back through cleanup, which is why cleanup lives at the tail, after the loop.
If a problem needs uniqueness with repeated letters, sort + skip-duplicates composes with used[] — yesterday's dedup and today's ordering stack cleanly.
Trace a 3-element example by hand once ([1,2,3] → six leaves) — knowing the exact emission order is what lets you debug permutation code cold.

```python
def permutations(nums):
    out, used, path = [], [False] * len(nums), []
    # used[i] means nums[i] is on the current path — try only the others
    def backtrack():
        if len(path) == len(nums):    # every element placed -> one permutation
            out.append(path[:])       # copy: path keeps mutating
            return
        for i in range(len(nums)):    # ORDER matters: try every unused element
            if used[i]:
                continue
            used[i] = True            # CHOOSE
            path.append(nums[i])
            backtrack()               # EXPLORE
            # (everything deeper runs with nums[i] in place on the path)
            path.pop()                # UN-CHOOSE
            used[i] = False
    # kick off with an empty path: depth 0 tries every element
    backtrack()
    return out                        # n! leaves, each assembled in O(n)
```

Watch-outs:
- The un-choose lines are the pattern — forgetting them leaves state poisoned for sibling branches, and the bug looks random.
- Copy at leaves (`path[:]`) and never share mutable state between branches — aliasing bugs here look like duplicated or missing results, never like a clean error.
- Word Search: the board must be restored on EVERY exit path, or sibling searches see phantom visited cells.
- Palindrome Partitioning: prune at chunk formation, not at the leaf — checking each candidate the moment you cut it is the difference between passing and TLE.
- Before coding, name the three things aloud: the choice at each level, the completion test, the cleanup — if any is fuzzy, the code will be too.
- used[] is for permutations; the start index is for combinations — mixing them is the single most common backtracking mistake. Say which one this problem needs and why.
- Prune early: if a prefix already violates a constraint (word mismatch, budget overrun, non-palindrome chunk), return before recursing — cheap checks first, expensive checks never.
