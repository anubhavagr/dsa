## 🔥 Pattern of the Day: Loop Order Defines the Object You Count
Two identical-looking loops, two different mathematical objects. With coins in the
outer loop you commit to one coin denomination at a time, so a multiset like
{1, 1, 2} is built exactly once — combinations. With the amount in the outer loop
you finish one target at a time and let any coin supply the last element, so
1+1+2, 1+2+1 and 2+1+1 are counted separately — permutations. Reach for this
pattern whenever a counting problem's answer changes under reordering: decide
whether order matters FIRST, in words, then let that sentence dictate the nesting.
Key invariant: dp state is always "answers using only what the loops have fixed
so far" — the outer loop is what you've committed to.

```python
def change(amount: int, coins: list[int]) -> int:
    # dp[a] = number of COMBINATIONS (multisets) building amount a from coins seen so far
    dp = [0] * (amount + 1)
    dp[0] = 1                                  # one way to make 0: use nothing
    for c in coins:                            # coins OUTER: commit to one coin at a time
        for a in range(c, amount + 1):         # ascending: reusing c is legal (unbounded)
            dp[a] += dp[a - c]
    return dp[amount]

def combination_sum4(nums: list[int], target: int) -> int:
    # dp[t] = number of PERMUTATIONS (ordered sequences) summing to t
    dp = [0] * (target + 1)
    dp[0] = 1
    for t in range(1, target + 1):             # amounts OUTER: finish one target at a time
        for c in nums:                         # any coin may supply the LAST element
            if c <= t:
                dp[t] += dp[t - c]
    return dp[target]
```

**Worked example** — `coins = [1, 2]`, `amount = 4`. Same inputs, same recurrence shape, different nesting:

Combinations (coins outer — each pass finalizes one coin):

| pass | dp[0] | dp[1] | dp[2] | dp[3] | dp[4] |
|---|---|---|---|---|---|
| after coin 1 | 1 | 1 | 1 | 1 | 1 |
| after coin 2 | 1 | 1 | 2 | 2 | 3 |

3 multisets: 1+1+1+1, 1+1+2, 2+2. There is no "2+1+1" row because coin 2's pass only
ever adds onto sums that already exclude 2.

Permutations (amount outer — every position distinct):

| t | dp[t] from | dp[t] |
|---|---|---|
| 1 | dp[0] | 1 |
| 2 | dp[1] + dp[0] | 2 |
| 3 | dp[2] + dp[1] | 3 |
| 4 | dp[3] + dp[2] | 5 |

5 sequences: 1111, 112, 121, 211, 22. Rule of thumb: the outer loop is what you
commit to first — commit to a coin and order evaporates; commit to a position and
order multiplies.
