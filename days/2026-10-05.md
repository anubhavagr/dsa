## 🔥 Pattern of the Day: Halve the search space with an invariant
Binary search is not "finding a number in a sorted array" — it is keeping one sentence true: the answer, if it exists, lives in [lo, hi].
Every branch must shrink the range while preserving that sentence; when you write it that way, the off-by-one bugs have nowhere to live.
Reach for it whenever a domain is ordered or a predicate flips exactly once — sorted arrays are only the most famous case.
On rotated arrays the extra move is identifying which half around mid is normally sorted, because a sorted half supports a range check in O(1).

```python
from bisect import bisect_left          # the stdlib ships this — use it in
                                        # real code, hand-roll it on a whiteboard
def search(nums, target):
    i = bisect_left(nums, target)
    return i if i < len(nums) and nums[i] == target else -1
```

```python
def bisect_left_hand(a, x):
    lo, hi = 0, len(a)                  # half-open: invariant is "answer in [lo, hi)"
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < x:
            lo = mid + 1                # answer, if any, is right of mid
        else:
            hi = mid                    # a[mid] >= x: mid itself could be it
    return lo                           # first index with a[i] >= x

def search_rotated(a, target):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == target:
            return mid
        if a[lo] <= a[mid]:             # left half [lo, mid] is sorted — trust it
            if a[lo] <= target < a[mid]:
                hi = mid - 1            # target provably in the sorted half
            else:
                lo = mid + 1
        else:                           # right half [mid, hi] is the sorted one
            if a[mid] < target <= a[hi]:
                lo = mid + 1
            else:
                hi = mid - 1
    return -1
```

Watch-outs:
- Closed interval [lo, hi] uses `while lo <= hi` and `hi = mid - 1`; half-open [lo, hi) uses `while lo < hi` and `hi = mid`. Pick one per function and never mix.
- `mid = (lo + hi) // 2` cannot overflow in Python — but say the `lo + (hi - lo) // 2` form out loud; interviewers listen for it.
- In the rotated case, `a[lo] <= a[mid]` (with the equals) is what keeps single-element sorted halves working — dropping the `=` breaks `[3,1]`.
