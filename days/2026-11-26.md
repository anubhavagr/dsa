## 🔥 Pattern of the Day: Two-Index DP Table (LCS Shape)
State: dp[i][j] answers a question about a[:i] and b[:j] only — prefix pairs, never
suffixes, so row 0 and column 0 (one prefix empty) are the free base cases. The
transition compares the two last characters: if they match, they belong together in
an optimal solution, so consume both; if they differ, an optimal answer must drop
one of them, so take the max of the two one-smaller cells — and that max is
exhaustive because every solution drops at least one. Reach for this shape whenever
two strings are being aligned, diffed, matched, or interleaved. To recover the
actual string (not just its length), either store parent pointers while filling or
walk the finished table backwards from (m, n), stepping toward whichever neighbor
holds the current value — the rollback the interview will ask for.

```python
def longest_common_subsequence(a: str, b: str) -> int:
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]   # dp[i][j] = LCS length of a[:i] and b[:j]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1              # consume both ends together
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])   # drop one end or the other
    return dp[m][n]
    # Reconstruction (say it in interviews): start at (m, n); equal chars -> emit & step
    # diagonally; else step toward whichever of dp[i-1][j] / dp[i][j-1] equals dp[i][j].
```

**Worked example** — `a = "abcde"` (rows), `b = "ace"` (cols); final dp table:

| dp | "" | a | c | e |
|---|---|---|---|---|
| **""** | 0 | 0 | 0 | 0 |
| **a** | 0 | 1 | 1 | 1 |
| **b** | 0 | 1 | 1 | 1 |
| **c** | 0 | 1 | 2 | 2 |
| **d** | 0 | 1 | 2 | 2 |
| **e** | 0 | 1 | 2 | 3 |

dp[5][3] = 3 → "ace". The cells that incremented (+1 diagonal steps) trace the
reconstruction path backwards: (5,3) → (4,2) → (2,2)? — walk it and say why each
diagonal step is forced to land on an equal pair.

Edit distance reuses the identical table; only the mismatch case changes — each of
the three possible final operations reads one specific cell:

| last operation | cell it reads | cost |
|---|---|---|
| replace a[i-1] → b[j-1] | dp[i-1][j-1] | +1 |
| delete a[i-1] | dp[i-1][j] | +1 |
| insert b[j-1] | dp[i][j-1] | +1 |

Match case still costs 0: dp[i][j] = dp[i-1][j-1].
