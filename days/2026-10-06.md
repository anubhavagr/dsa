## 🔥 Pattern of the Day: feasible(mid), then binary search the answer space
When a problem asks for the smallest/largest value of some knob such that a budget holds, stop searching the array — search the knob's range.
Write a greedy `feasible(x)` check first (usually one linear pass), argue it is monotone (true above the answer, false below it), then binary search x.
The two bounds come from the problem's physics: the smallest candidate that is not obviously impossible, and the value that trivially works.
Reach for it on "minimize the maximum", "minimum capacity/speed/size such that...", whenever a budget can be checked greedily for a fixed knob value.
Invariant: lo is always infeasible-or-candidate, hi is always feasible — they meet at the first feasible value.

```python
def min_cap_linear(weights, days):     # try EVERY capacity: O(sum · n)
    for cap in range(max(weights), sum(weights) + 1):
        need, load = 1, 0
        for w in weights:
            if load + w > cap:
                need, load = need + 1, w   # a new day must start
            else:
                load += w
        if need <= days:
            return cap
```

```python
def min_cap(weights, days):            # binary search the answer: O(n log sum)
    def feasible(cap):                 # can we ship within `days` at this cap?
        need, load = 1, 0
        for w in weights:
            if load + w > cap:         # cap can't absorb w today
                need, load = need + 1, w
            else:
                load += w
        return need <= days

    lo, hi = max(weights), sum(weights)   # physical floor and trivial ceiling
    while lo < hi:                        # find the FIRST feasible cap
        mid = (lo + hi) // 2
        if feasible(mid):
            hi = mid                   # feasible -> the answer is mid or lower
        else:
            lo = mid + 1               # infeasible -> must go bigger
    return lo
```

Watch-outs:
- The check is greedy and never backtracks — if your feasibility check needs backtracking, the pattern does not apply.
- Monotonicity is the whole contract: say "if cap works, every larger cap works too" out loud before trusting the search.
- The same loop solves "smallest x" (hi = mid on true) and "largest x" (lo = mid on true, with a mid+1 flavor) — know which direction the problem wants.
