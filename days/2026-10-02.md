## 🔥 Pattern of the Day: Expand, then shrink while invalid
The right edge is a for-loop: it always moves, one step per iteration, because every element deserves to enter the window.
The left edge is a while-loop: it moves only while the window is broken, and it stops the instant validity returns — that asymmetry is the entire pattern.
Longest-valid windows are measured after shrinking; shortest-valid windows are measured before shrinking, while still bloated.
Reach for it when a constraint on a substring/subarray can be violated and repaired locally (a repeat, one too many zeros, a missing letter).
Invariant: at the end of each iteration, [left..right] is the smallest valid window ending at right (or the repair is still in progress).
Complexity to narrate: right advances n times; left advances at most n times across the ENTIRE run — that total-work argument is why the nested while is still O(n).
Compare with yesterday: fixed windows know their size and never shrink past it; variable windows let the left edge chase validity — same skeleton, the shrink condition is the only new idea.
For shortest-valid problems the polarity flips: shrink while STILL valid, record before breaking validity — every window you measure is a candidate, not a record to beat.
Stale-state windows (the replacement problem's frequency count) tolerate lazy updates because an over-estimate never wrongly shrinks — ask whether your validity predicate can say the same.
Write the validity predicate in plain words before any code — "no character repeats", "at most k repairs needed" — the code is a transliteration of that sentence.

```python
def longest_unique_brute(s):           # the nested-rescan instinct: ~O(n^2)
    best = 0
    for i in range(len(s)):
        for j in range(i, len(s)):
            if len(set(s[i:j + 1])) < j - i + 1:
                break                  # repeat inside s[i..j]
            best = max(best, j - i + 1)
    return best
```

```python
def longest_unique(s):
    count = {}
    # char -> its count inside the current window [left, right]
    left = best = 0
    for right, ch in enumerate(s):
        count[ch] = count.get(ch, 0) + 1      # 1) expand: always absorb s[right]
        while count[ch] > 1:                  # 2) invalid: ch now repeats
            count[s[left]] -= 1              #    shrink from the left only
            left += 1                         #    while the break persists
        best = max(best, right - left + 1)    # 3) window [left, right] is valid
    return best                               # (never contains a repeat here)
```

Watch-outs:
- The shrink loop is `while`, not `if` — one eviction often is not enough to repair the window.
- Empty string, single character, all-identical input: three cheap tests that catch most window bugs before submission.
- Name the edges window_left / window_right (or l / r consistently) — swapping variable names mid-interview is how people confuse themselves aloud.
- For shortest-window problems (min window substring), grow greedily and shrink greedily but record BEFORE you make the window invalid again — the measurement point flips.
- A stale maximum (e.g. most-frequent-char count in the replacement problem) is only ever optimistic, and an optimistic cap still shrinks correctly — probe that idea when you get there, it is the classic follow-up.
