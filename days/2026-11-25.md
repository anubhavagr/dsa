## 🔥 Pattern of the Day: Patience Sorting (bisect) + Counting LIS
Maintain tails, where tails[k] is the smallest possible tail of any strictly
increasing subsequence of length k+1. The array stays sorted — that is the entire
reason binary search is legal. Each new x either extends the longest chain (append)
or lowers an existing tail (replace), which never changes any achievable length
today but strictly improves tomorrow's options. Reach for it on any "longest chain
under a < relation" problem; swap bisect_left for bisect_right when the relation
is ≤. Two caveats to say out loud: tails is the right LENGTH, not an actual LIS,
and when the problem asks HOW MANY longest chains exist, drop to the O(n²) twin
arrays (best length ending at i, ways to reach it) because the compressed array
has thrown away the path information.

```python
from bisect import bisect_left

def length_of_lis(nums: list[int]) -> int:
    tails = []                    # tails[k]: smallest tail of any increasing subseq of length k+1
    for x in nums:
        i = bisect_left(tails, x) # strictly increasing -> bisect_left (bisect_right for <=)
        if i == len(tails):
            tails.append(x)       # x extends the longest chain seen so far
        else:
            tails[i] = x          # x lowers the best tail for length i+1
    return len(tails)

def find_number_of_lis(nums: list[int]) -> int:
    n = len(nums)
    length, count = [1] * n, [1] * n   # best length ending at i, and number of ways to get it
    for i in range(n):
        for j in range(i):
            if nums[j] < nums[i]:
                if length[j] + 1 > length[i]:
                    length[i], count[i] = length[j] + 1, count[j]  # longer: restart tally
                elif length[j] + 1 == length[i]:
                    count[i] += count[j]                           # tie: add its ways
    best = max(length, default=0)
    return sum(c for l, c in zip(length, count) if l == best)
```

**Worked example A — tails trace** for `nums = [10, 9, 2, 5, 3, 7, 101]` (LIS length 4):

| x | action (bisect index) | tails after |
|---|---|---|
| 10 | append (0) | [10] |
| 9  | replace idx 0 | [9] |
| 2  | replace idx 0 | [2] |
| 5  | append (1) | [2, 5] |
| 3  | replace idx 1 | [2, 3] |
| 7  | append (2) | [2, 3, 7] |
| 101 | append (3) | [2, 3, 7, 101] |

Note tails never claims to BE a subsequence of the input — only its length is the answer.

**Worked example B — counting trace** for `nums = [2, 5, 3, 7]`:

| i (value) | length[i] | count[i] |
|---|---|---|
| 0 (2) | 1 | 1 |
| 1 (5) | 2 | 1 |
| 2 (3) | 2 | 1 |
| 3 (7) | 3 | 2 |

Best length 3 reached in 2 ways ([2, 5, 7] and [2, 3, 7]) — the tie at j = 2 is what
adds count[2] into count[3].
