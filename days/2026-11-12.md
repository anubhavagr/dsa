## 🔥 Pattern of the Day: Union-Find — Compress & Rank
Union-Find answers "are these two in the same set?" *incrementally*, as edges arrive — something DFS must redo from scratch.
`find` walks to the root, then path-compression re-hangs every node it passed so the next find is nearly flat. `union` attaches one root under the other by rank to keep trees shallow, and returns False when the endpoints were already connected — which is precisely a "redundant edge" or "cycle just formed" signal. Together the two optimizations give amortized near-constant time.

- **Reach for it when:** edges arrive incrementally and you only need to know whether two nodes are connected — not the actual path between them — which is exactly the setting where a DFS would have to restart from scratch after each new edge.
- **Key invariant:** Each component always has exactly one root, and that root serves as the component's identifier — two nodes are in the same set if and only if find returns the same root for both.
- **Watch out:** Unioning the two nodes themselves instead of their find() roots is the most common implementation bug: it attaches a mid-tree node under another tree while the old root stays alive, leaving one component with two roots and breaking later same-set answers.
- **How to say it in an interview:** "Every connected component has exactly one root node that names it, so union must attach one root under the other — never the raw nodes. find walks to the root and then path-compression re-hangs every node it passed so the next find is nearly flat, union by rank keeps the trees shallow, and together the operations run in amortized near-constant time. A union that returns False means the endpoints were already connected — which is exactly the 'redundant edge' or 'cycle just formed' signal."
- **Test with:** unioning two nodes that are already connected (the operation must report no change) · find on a node never unioned before (it is its own root) · a long chain of unions in one direction (path compression must keep the tree depth tiny).
- **Complexity:** With both path compression and union by rank, each operation costs amortized α(n) — the inverse Ackermann function, at most 4 for any realistic n, so effectively constant — and the parent and rank arrays take O(n) space.

```python
class UF:
    def __init__(self, n):
        self.parent = list(range(n))      # everyone starts alone
        self.rank = [0] * n               # union by rank keeps trees flat

    def find(self, x):
        root = x
        while self.parent[root] != root:  # walk up to the root
            root = self.parent[root]
        while self.parent[x] != root:     # path compression: re-hang all
            self.parent[x], x = root, self.parent[x]
        return root

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False                  # already connected (edge redundant)
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra               # attach the shorter under taller
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True
```
